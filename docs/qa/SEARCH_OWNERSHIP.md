# Captured ownership and retained search anchors

For contributors fixing the creation regression from the candidate-coverage study.
This contract precedes real-source queries. Keep earlier protocols, raw results and
oracles unchanged. No model, browser feature or repository-specific search rule is added.

## Required behaviour

Use captured scope names/parents before topic admission, so a constructor using Self or
an implicit Python receiver can match its enclosing type even in a generic filename.
A strong ownership signal matches a complete captured identifier to a normalised topic;
mentioning that topic in a parameter or composite owner name is weaker. Do not parse
trait/generic names into invented semantic owners or claim resolved type/call relationships.
Keep body/path matches as other discovery signals.

Retain compact baseline excerpts that have a strong captured-topic match and visible or
captured operation evidence, prioritising one anchor per topic within the same bounds.
Retain their exact source/content/range identities while relabelling final result positions.
Keep byte ranges privately in native evidence rather than guessing them from text/lines;
the serialized evidence interface remains unchanged. A stale context remains invalid.

Prioritise strong captured ownership before generic operation richness. Give distinct
captured declaration names a first pass within each operation pool, then retain remaining
same-name candidates as backfill. This is display diversity, not proof that same-name
methods are equivalent. Preserve scope/overlap suppression, literal UTF-8 bounds and the
eight-result/4,000-byte comparison limits. Other question forms still use compact unchanged.

## Validation and fixed comparison

Use TDD with generic filenames, unrelated Rust/Python types, implicit receivers, wrappers
that merely mention the topic, crowded same-name lifecycle methods, baseline identity
retention, duplicate-name backfill, small budgets and source replacement. Test through
Corpus and native transport interfaces. No new dependency or unsafe code is required.

After the focused tests pass, run serial low-priority whole-module mutations and normal
formatting/workspace tests/doctests/Clippy. Keep one mutant job and one compiler/jobserver
task. Report equivalent, unviable and timed-out variants separately. Test the new evidence
range field through its serialized/source-bound interface; do not expose it to clients.

Freeze the same fifteen known development questions, seven preferred locators, 22 broader
anchor targets and scope/literal alternatives from the earlier coverage cohort. Compare
compact and revised search at eight results/4,000 bytes, with three alternating-order
repetitions. This uses known counterexamples and is not held-out acceptance. All eight
reserved real-source cases remain unrun; no inference is performed.

Record the previous compact/search pools as historical controls. Require no loss of the
previous four search locator gains and restoration of the constructor and ordinary Task
entry before considering the revision an improvement. Keep the registration-table miss
visible unless a frozen locator is actually present; do not replace targets with observed
alternatives after queries. Anchor hits do not establish complete answers or semantic edges.

Measure optimized native/round-trip query times and process-tree PSS after all correctness,
mutation and build work. Account for compact baseline work inside revised search. Keep the
one-second median warm-query and 4-GiB observed PSS targets without enforcing or silently
relaxing them. One native index, serial requests, nice 10; stop the owned process.

If an important locator is still missing or a control worsens, retain that result without
another policy change in this cohort. Viewer integration, model query planning and broader
source-role corrections remain separate work.
