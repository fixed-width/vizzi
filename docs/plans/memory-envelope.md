# Qualify the combined engine and browser memory envelope

Measure simultaneous process memory through the real browser workload before choosing
source-backing defaults. Keep engine/library policy separate from experimental resource
observation. Linux procfs and cgroups remain outside portable application interfaces.

## Workload and accounting

Compare resident/default source and opt-in spooling on each pinned Linux/PyTorch profile.
Use four workers, active native watching and ordinary two-second recovery. Keep syntax
retention/input admission disabled to avoid changing several policies together.
Use three steady and three batch-refresh motion samples, picking, ten ordinary edits
following distinct observed recovery passes, and a large-header opening/edit. Require
bounded browser delivery, visible source markers and final clean-capture agreement.
Original archives remain unchanged; edited copies are disposable.

A separate safe Rust observer samples itself and its descendants, including the Node
driver, native host, Chromium processes and concurrent clean-verification host. Record
simultaneous PSS/RSS sums, process identities/start times, missing/error diagnostics and
sampling duration. Never add independent process high-water marks. Ancestry can miss
orphans and transient processes; sampled sums can miss peaks and cannot enforce physical RAM.

The capped procedure uses one fresh cgroup per condition: 12 GiB memory maximum and
zero swap allowance, leaving a provisional 4 GiB outside the group in the 16 GiB model.
Verify actual controls, child membership, group memory/peak and OOM counters. Read cgroups
without modifying them. Missing controls, changed limits or incomplete evidence cannot
produce a capped success. This group budget does not emulate an editor, integrated GPU,
OS workload or physical laptop.

Provide an explicit observe-only mode for environments without cgroup access. Its reports
always mark enforcement false. Preserve exact failed capability probes and never relabel
address-space limits or low observed usage as constrained-memory qualification.

## Validation and delivery

Use TDD for proc parsing, process ancestry, simultaneous aggregation, vanished processes,
strict cap/membership/OOM guards and command result propagation. Run the complete affected
mutation scope, workspace tests/doctests, formatting, Clippy and browser checks. Build and
prepare facts before timed runs; no competing verification/preparation work during timing.

Keep the reproduction procedure, observations and remaining constrained-run requirement
separate from this plan. Do not change production policy based on uncapped observations.

## Delivery status

The [report](../../experiments/memory-envelope/RESULTS.md) records completed capped and
matching observe-only matrices. The approved benchmark entry point can create scopes even
though direct managed-shell probes fail. Desktop-bus isolation prevents Chromium's main
process from leaving the scope; the observer still rejects escaping members. All four
capped cases pass within 12 GiB without swap/OOM/limit events. Pressure behaviour and
physical laptop qualification remain open; no default-policy decision follows.
