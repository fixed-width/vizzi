# Captured ownership: constructor restored, qualification still fails

For contributors fixing source search before product integration. **This revision restores
the transaction constructor and moves the validator first, but still finds only 4/7 frozen
locators. The ordinary Task caller remains missing and the receiver is lost.** It does not
meet the predeclared improvement criterion. Keep selector defaults unchanged.

The [contract](../../docs/qa/SEARCH_OWNERSHIP.md) precedes queries. The
[source-card comparison](results/search-ownership/trial.md) preserves the compact control
and revised search. No model, reserved-case query or viewer feature is involved.

## Implementation and controlled inputs

Captured scope names/parents now contribute before topic admission. Exact complete
identifier matches are stronger than incidental body/path mentions or composite names.
This admits constructors that use Self and implicit Python receivers in generic files.
It remains lexical scope evidence, not resolved semantic ownership; generic/trait names
are not parsed into guessed owners.

The selector retains operation-related compact excerpts with a strong captured topic,
one anchor per topic, preserving their source/content/range identity. Native evidence now
stores byte ranges privately; they are omitted from JSON. Distinct captured declaration
names get a first pass within each operation pool, followed by same-name backfill.
Existing literal, count, overlap and stale-context bounds remain in force.

The same fifteen known questions, seven preferred locators, 22 broader source-anchor
targets and literal/scope alternatives are checked against the preceding cohort before
execution. Code/oracles are frozen, then ninety serial paired observations run on one
current index with three alternating-order repetitions. All thirty distinct pools repeat
identically. No question, target, policy or limit changes follow observed results.

The source archive/revision remains pinned, with 931 files, 10,754,851 selected bytes and
22,821 windows. Only the experimental QA implementation changes index identity; raw
core/browser analysis is unchanged. Historical study snapshots remain separate.

## Locator results and counterexample

| Frozen locator | Previous search rank | Revised search rank | Current compact rank |
| --- | ---: | ---: | ---: |
| Transaction constructor | — | 1 | 3 |
| Ordinary Task entry | — | — | — |
| Efun macro definition | 1 | 1 | — |
| Efun invocation/table | — | — | — |
| Commit receiver | 1 | — | — |
| Commit validator | 7 | 1 | — |
| FutureVersion rejection | 7 | 1 | — |

Revised search and the previous selector each find 4/7 locators; compact finds 1/7.
All four revised hits have visible literal markers. The constructor retains the exact
identity of its compact baseline excerpt while moving to first position. Byte ranges
remain hidden in all serialized results. Scope-only alternatives add no hits here.

The creation pool is now dominated by Transaction members: the constructor, copy-on-write
helpers, fields and pending-view methods. The earlier alternative begin_attempt creation
sites disappear along with the still-missing Task entry. For commits, the validator and
its first rejection are prominent, but the receiver is displaced by other transactional
members and validation-related material. The efun macro remains first; its invocation is
still absent. Finding one branch does not supply every requested check or the full path.

This exposes a ranking trade-off, not a successful fix. Inspection suggests that ownership
is being applied too broadly across operation pools: belonging to Transaction promotes
ordinary members ahead of external creation/dispatch sites. Names/ancestor words and
incidental operations can make those members appear relevant. This diagnosis is based
on implementation/result inspection, not a separately isolated causal test.

All twelve broader controls return identical contexts between current selectors, with
11/22 original literal targets found in each. No broader control loses a target. That
preserves the baseline but does not establish complete source coverage or user usefulness.
These are known development locators; alternative useful locations are not silently
substituted for missing preferred targets after the run.

## Cost and verification

Retained-baseline work is included inside revised search time.

| Focused question | Compact median native query | Revised search median native query |
| --- | ---: | ---: |
| Transaction creation | 499.0 ms | 542.6 ms |
| Add an efun | 560.5 ms | 609.6 ms |
| Commit path/checks | 405.5 ms | 475.3 ms |

Across all 45 observations per selector, median native time is 562.5 ms for compact and
554.5 ms for revised search; the delegated controls dominate that aggregate. Both meet
the provisional one-second median target. The prior recognised-query path took 16–31 ms;
that earlier timing excluded the compact baseline now being retained. It is a cost trade-off,
not a controlled claim about hardware speed or statistically independent user tasks.

Whole observed time is 61.32 seconds. Peak process-tree PSS is **0.113 GiB**, including
one native index, driver and observer, with no model. The 4-GiB observed target passes.
The observer samples at 250 ms, reports no errors and enforces no cap. Neither per-query
peak memory nor a physical laptop/editor workload is qualified. The owned process stops.

Fresh workspace tests/doctests pass: **486 tests**. All **20 serial QA test files**,
formatting, all-target Clippy and optimized native builds pass. Twelve ownership fixtures
cover generic filenames, Rust/Python implicit owners, repeated names, test exclusions,
anchor fairness, exact identity, byte budgets and source replacement. The original three
ownership/caller fixtures were observed failing before implementation.

Whole-module mutation work tests 96 variants, with baseline-checked retests after stronger
fixtures: **88 caught, four reviewed equivalents, three unviable and one timeout**. The
timeout changes the exhausted-pool guard and fails to terminate on a missing topic; it is
separate from mutations caught by failing tests. The unmodified empty-topic checks pass.
The equivalents concern distinct bit positions, duplicated input rejection and a zero-mask
optimization; their extra work/performance is outside correctness mutation checks.

The supplemental range-storage diff generated only an Evidence::default replacement that
cannot build. It supplies no viable mutation coverage of the field assignment; serialization,
identity and budget tests exercise that interface. Prior Node-helper mutation evidence is
retained with its identical source hash, not rerun. All mutation jobs use one low-priority
worker/compiler task. The [review](results/search-ownership/mutation-review.json) keeps
exclusions, unviable builds and timeout evidence separate.

Clippy required a name for the six-part priority tuple. The alias changes no executable
function body: all eight mutation-tested functions are verified byte-identical and the
96-mutant inventory is unchanged. The [verification](results/search-ownership/validation/alias-verification.json)
and both source versions are archived. Core/browser/vizzi host source is unchanged from
7219417, so the prior complete browser pass is retained, not rerun.

The [archive](results/search-ownership/) retains raw responses, all source cards, frozen
identities, historical target comparisons, timing/memory and validation evidence.
All 442 checksummed historical payloads across sixteen archives remain unchanged. Follow
[the procedure](SEARCH_OWNERSHIP.md) to reproduce the comparison. All eight reserved cases
remain unrun; no dependency, unsafe code, inspected build or model call is added.

The revision remains experimental. The counterexample points toward separating declaration
ownership from usage/entry evidence, so an owning type's ordinary members cannot crowd out
its external callers. That role distinction should be validated before further ranking
weights or viewer integration; the baseline remains available throughout.
